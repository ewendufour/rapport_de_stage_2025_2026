\subsection{La théorie des types dépendants.}

\paragraph{Un système de preuves.}
Une théorie des types est un système de preuves formelles dans lequel on s'intéresse aux programmes bien typés. 
Celle-ci est définie par un ensemble de termes (programmes) que l'on peut construire, 
un ensemble de types que l'on peut construire, ainsi qu'un ensemble de règles de typage afin d'attribuer des types aux termes.
Nous notons $t : T$ pour indiquer qu'un terme $t$ est de type $T$ et $\Gamma \vdash t : T$ que le contexte $\Gamma$ permet de déduire que $t$ est de type $T$.

\begin{minipage}{0.45\textwidth}
\centering
\textbf{Types}
\[
\tau ::= \iota \mid \tau \to \tau
\]

\textbf{Termes}
\[

\]

\textbf{Contextes}
\[

\]

\paragraph{Correspondance de Curry-Howard.}
Dans ses travaux, Howard établit un lien profond entre les propositions de la logique intuitionniste et les types.
Via cette correspondance, prouver qu'une formule $A$ est vraie revient exhiber un programme construisant un objet de type $A$.
En enrichissant nos types en permettant aux types de dépendre de termes, 
on obtient un système de preuves dans lequel on peut décrire tous les énoncés mathématiques.

\paragraph{Assistants à la preuve.}
Les assistants à la preuve comme Rocq, Lean et Agda sont basés sur des théories des types dépendants.
Dans ces systèmes, on décrit un énoncé à prouver via un type ainsi qu'(une manière de construire) un terme de preuve 
et l'assistant vérifie que le terme possède le bon type. 
Dans la figure \ref{fig:agda-proof}, la première ligne permet de spécifier le type (l'énoncé) à prouver, 
et la deuxième décrit un terme (une preuve) de ce type.

\begin{figure}[h]
\centering
\begin{minted}{agda}
  modus-ponens : {A B : Prop} → (imp : A → B) → (a : A) → B
  modus-ponens imp a = imp a 
\end{minted}
\caption{Preuve du modus ponens en Agda}
\label{fig:agda-proof}
\end{figure}

\subsubsection{Fonctionnement d'Agda et appel à Canonical}
\paragraph{Mode interactif.}
Au-delà de vérifier les preuves qui lui sont fournies, 
l'assistant de preuve Agda peut s'utiliser de manière interactive afin d'aider l'utilisateur à rédiger sa preuve.
Nous pouvons spécifier à Agda que la preuve est incomplète en laissant un $?$ au sein du terme de preuve comme montré dans la figure \ref{fig:agda-proof-uncomplete}.
De cette manière, Agda va créer un nouveau but et lui affecter le type que le terme manquant devrait avoir pour compléter la preuve.
Par exemple, en compilant le code en figure \ref{fig:agda-proof-uncomplete}, Agda va créer le goal $0$ montré en figure \ref{fig:agda-proof-uncomplete-compiled}.
Les termes $A$, $B$ étant implicitement introduits et le terme $imp$ explicitement introduit, Agda en déduit que le goal $0$ doit être de type $A \to B$. 
L'utilisateur peut ainsi se placer dans le goal $0$ et écrire un terme qu'il fournira par la suite à Agda afin de compléter sa preuve.

\paragraph{Appel à Canonical.}
Dans le but d'aider l'utilisateur à remplir le goal dans lequel il se trouve, 
nous souhaitons implémenter une commande qui récupère le type du goal courant et le fourni à Canonical.
Deux solutions ont été envisagées afin de répondre à cette problématique.
La première solution est de passer par le langage de reflection de Agda. 
Celui-ci permet d'écrire des tactics de résolution directement comme des termes d'Agda.
La deuxième solution consiste à implémenter une fonction d'appel à Canonical directement dans l'assistant lui-même dans son code Haskell.
Nous récupèrons les types des goals écrit dans la syntaxe interne des termes d'Agda puis, après une passe de transformation, 
envoyons le type de goal à Canonical via la FFI de Haskell.
Étant la solution en partie utilisée par Mimer et pour des raisons d'ergonomie, nous avons choisi de nous concentrer sur la deuxième solution.
